# 设计决策记录（ADR）

记录已拍板的设计决策及其理由。格式：背景 / 选项 / 决定 / 理由 / 影响。

---

## ADR-001 — 角色即存档槽，支持多角色

**状态**：已决定（2026-10-26）

**背景**
三职业（战士 / 法师 / 道士）的进度如何组织？是一个存档里切职业，还是分开？

**选项**
- A. 分别开档，每职业一个固定存档
- B. 单存档内可切换职业，进度共享
- **C. 多存档槽：创建角色即占用一个槽位，同职业可创建多个**

**决定：C**

**理由**
比 A 更贴近原作的角色列表体验（传奇登录后就是选角色界面）。允许开两个战士，意味着玩家可以做"主号 + 实验号"——后者用来试武器升级、试不同技能加点，而不用担心毁掉主号。这对一个赌博系统（见 ADR-003）是必要的配套。

**影响**
- 存档从"单文件"变成"槽位目录"，每个槽位独立目录 + 独立 RNG 状态
- 启动流程多一层：角色列表 → 选择 / 创建 / 删除 → 进入游戏
- 离线收益**只对载入的角色结算**，其他槽位的 `last_saved_at` 不推进（否则等于多开挂机，破坏平衡）
- 删除角色需要二次确认（不可恢复）
- 新增任务 T9.5（见 `05-roadmap.md`）

## ADR-002 — 死亡不掉装备，另开高风险模式

**状态**：已决定（2026-10-26）

**背景**
原作死亡掉经验 + 概率掉装备。挂机场景下，玩家离线期间丢失顶级装备会直接导致流失。

**选项**
- A. 只掉经验
- B. 保留原作掉装备
- **C. 默认只掉经验，提供可选的「高风险模式」**

**决定：C**

**理由**
把原作的紧张感做成玩家自愿承担的选项，而不是强制惩罚。实现成本只比 A 多一个开关和一个掉落率系数。

**影响**
- 默认：损失当前等级经验条 5%，不掉级，不掉装备，回安全区休息 300 tick
- 高风险模式（角色创建时选择，**创建后不可更改**）：掉落率 +50%，死亡时掉一件未锁定装备
- 装备需要「锁定」标记 + UI 操作
- 高风险角色在角色列表里要有显著标识

## ADR-003 — 武器升级失败碎裂，幸运符可保护

**状态**：已决定（2026-10-26）

**背景**
传奇的武器升级是赌博式玩法（黑铁矿 + 首饰 + 金币 → 成功加属性 / 失败碎武器）。失败碎主武器在挂机游戏里会打断数小时进度。

**选项**
- A. 碎（原汁原味）
- B. 不碎，失败只消耗材料
- **C. 碎，但有「幸运符」消耗品可保护**

**决定：C**

**理由**
保留赌博的刺激，同时把它从纯 roll 点转化为资源管理——玩家要决定"这枚幸运符留给第几次升级"。幸运符靠挂机掉落获取，于是挂机时长本身成为赌博资本。

**影响**
- 新增消耗品「幸运符」及其掉落表位置
- 升级 UI 必须显示当前成功率 + 二次确认（会碎武器的操作绝不能手滑触发）
- 幸运符保护触发时要有明确反馈（"幸运符碎裂，武器保住了"）

## ADR-004 — 稀有掉落加保底计数器

**状态**：已决定（2026-10-26）

**背景**
纯随机掉落在挂机游戏里有真实的尾部风险：0.2% 掉率、一天 8000 次击杀，仍有约 1/5000 的玩家颗粒无收。

**选项**
- A. 纯随机（原作行为）
- **B. 加 pity 计数器，击杀 N 次必掉**

**决定：B，阈值设为期望次数的 3 倍**

**理由**
阈值设得高，能保住绝大多数玩家"爆装备"的随机惊喜，只砍掉最极端的挫败案例。

**影响**
- `GameState` 需要 `pity: BTreeMap<(MonsterId, ItemId), u32>` 计数器，随存档序列化
- 只对 `chance < 0.01` 的掉落项启用
- 阈值由掉率自动推导（`ceil(3 / chance)`），不手工配置，避免数据表膨胀
- 保底触发的掉落在日志里**不要**特殊标注（否则玩家知道是保底，惊喜感反而没了）

## ADR-005 — 以 1.67 为主体，顶级内容引入 1.76 的赤月 / 牛魔

**状态**：已决定（2026-10-26）

**背景**
1.67 的内容天花板大致在祖玛（Lv.45 左右）。赤月峡谷、牛魔寺庙、屠龙、圣战 / 法神 / 天尊套装很可能是 1.76+ 才加入的。严格限制在 1.67 会导致挂机进度两周见底。

**选项**
- A. 严格 1.67，到祖玛教主为终点
- **B. 以 1.67 为主体，顶级内容引入 1.76 的赤月 / 牛魔**
- C. 严格 1.67，自行原创后期内容

**决定：B**

**理由**
C 会违背"所有内容来源于原作"的前提，A 撑不住挂机游戏所需的进度长度。B 的妥协最小——玩家看到的仍然全是真实的传奇内容，只是跨了一个小版本。

**影响**
- 数据文件中每个条目加 `version_origin: "1.67" | "1.76"` 字段，便于溯源和后期审计
- README 中明确说明："主体还原 1.67，顶级内容取自 1.76"
- `06-content-reference.md` 里的 `⚠️` 标记不再是阻塞项，但仍需保留以供核对

## ADR-006 — 衣服分男女款

**状态**：已决定（2026-10-26）

**背景**
原作衣服分为"重盔甲(男)"/"重盔甲(女)"两件独立物品。

**决定：分男女**

**理由**
实现成本极低（数据表一列 + 穿戴判定一个分支），但"捡到女装只能卖掉"是老玩家的记忆点。

**影响**
- 角色创建时需要选择性别
- `ArmorDef` 增加 `gender: Male | Female` 字段
- 穿戴时校验性别匹配，不匹配时 UI 要说明原因（而不是只置灰）
- **掉落表里衣服类掉率按 2 倍给**，否则实际获取效率会腰斩

## ADR-007 — 自动喝药：可调 + 精度随进度解锁

**状态**：已决定（2026-10-26）

**背景**
挂机游戏必须有自动续航。配置的开放程度是一个进度感来源。

**决定：C — 可调，且调节精度随进度解锁。先按固定值实现，T14 再升级。**

**理由**
"自动化能力本身作为奖励"是挂机游戏里性价比最高的进度设计。但这条不阻塞主流程，所以先用固定阈值跑通，后期再分层解锁。

**影响**
- T4 阶段：写死 HP<50% / MP<30%，阈值从 `balance.ron` 读
- T14 阶段：解锁链设计为 开关 → 粗调（25%/50%/75%）→ 精调（1% 步进）→ 药水规格偏好
- 阈值配置属于角色存档，不是全局配置
