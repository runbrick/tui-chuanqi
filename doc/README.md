## 怎么用这套文档

1. 先读 `01` 和 `02`，确认技术栈和架构你认可（这两个决定后期返工成本最高）。
2. 读 `03` 确认玩法方向，`decisions.md` 是已经拍板的七条设计决策及理由。
3. 之后一直待在 `05-roadmap.md`，按 `T0 → T1 → ...` 顺序做，每个任务都有明确产出和验收标准。
4. `04` 和 `06` 是做任务时的查阅材料，不用一次读完。

## 一句话总结方案

**Rust + ratatui**，把游戏核心做成一个**纯函数式、确定性、不依赖 IO 的 `game-core` crate**（固定 100ms 逻辑 tick，RNG 按存档种子播种），TUI 只是它的一个渲染前端；所有传奇内容走**外部数据文件（RON）**驱动，不写死在代码里。

## 内容准确性说明

1.67 是 2003 年前后的版本，网络上的资料互相冲突（很多攻略混入了 1.76 / 1.80 的内容）。`06-content-reference.md` 里我把把握不大的条目标了 `⚠️待核实`。处理方式：**先用这份草稿把系统跑通，内容正确性靠后期替换数据文件修正** —— 这也是把内容外置成数据文件的主要理由。

版本范围已由 **ADR-005** 定下：以 1.67 为主体，顶级内容（赤月 / 牛魔）引入 1.76，数据条目带 `version_origin` 字段溯源。
