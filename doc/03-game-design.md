# 玩法设计

## 设计基调

**传奇的数值骨架 + 增量游戏的进度曲线。**

传奇本身就有很强的挂机属性（当年挂机刷沃玛就是主流玩法），所以不需要魔改。要做的是：
- 保留传奇的**战斗数值感**：攻击 / 防御都是区间随机，防御能完全吃掉伤害（"抵挡"），命中靠准确对敏捷；
- 补上传奇没有的**增量游戏节奏**：清晰的解锁阶梯、永久性成长、离线收益、"再玩五分钟"的钩子。

## 核心循环

```
挂机打怪 → 经验 + 金币 + 装备掉落
   ↓             ↓            ↓
  升级        买药 / 修装备   换装 / 强化
   ↓             ↓            ↓
   └──→ 解锁更深地图 → 更强的怪 → 更好的掉落 ─┘
```

四条成长线并行，玩家永远有事可做：

| 成长线 | 驱动 | 上限 |
| --- | --- | --- |
| 等级 | 经验 | 软上限（经验表指数增长） |
| 装备 | 掉落 + 强化 | 硬上限（屠龙 / 圣战 / 法神 / 天尊） |
| 技能 | 技能书 + 熟练度 | 硬上限（各技能 3 级） |
| 地图解锁 | 等级 + 前置地图通关 | 硬上限（内容量） |

## 职业

1.67 的三职业，**第一版只做战士，第二版补法师和道士**（见 roadmap T6）。

| 职业 | 核心属性 | 挂机特点 | 设计侧重 |
| --- | --- | --- | --- |
| **战士** | 攻击（DC）、准确 | 高血高防，靠喝金创药续航 | 最简单，伤害直给；烈火剑法做成蓄力型爆发 |
| **法师** | 魔法（MC） | 伤害最高但 MP 是瓶颈，脆 | 挂机核心矛盾 = 魔法药消耗；群伤对多怪地图收益高 |
| **道士** | 道术（SC） | 续航最强，召唤物分摊伤害 | 宝宝（骷髅 / 神兽）做成第二个战斗单位；毒 debuff |

> ✅ **已定（ADR-001）**：**角色即存档槽**。创建角色就占用一个槽位，同职业可以开多个（比如两个战士）。
> 进度完全独立，包括已解锁地图。离线收益只对载入的角色结算 —— 其他槽位不推进时间，否则等于多开挂机。

## 属性

沿用传奇的属性名，玩家看着亲切：

| 属性 | 原作名 | 作用 |
| --- | --- | --- |
| HP / MP | 生命 / 魔法 | — |
| 攻击 | DC | 物理伤害区间，如 `12-20` |
| 魔法 | MC | 法师法术伤害区间 |
| 道术 | SC | 道士法术 / 治疗 / 宝宝强度区间 |
| 防御 | AC | 物理减伤区间 |
| 魔防 | MAC | 法术减伤区间 |
| 准确 | 准确 | 命中判定 |
| 敏捷 | 敏捷 | 闪避判定 |
| 攻速 | — | 攻击间隔（毫秒）。原作叫"攻击速度"，这里直接用间隔表示 |

## 战斗公式

每个 tick 推进战斗状态机。**一次攻击的判定顺序**：

### 1. 命中判定

```
命中率 = clamp(0.75 + (攻击方准确 - 防御方敏捷) * 0.05, 0.15, 0.98)
```

传奇原版的准确 / 敏捷是小整数（装备上常见 +1 ~ +3），所以单点权重给得大。上下限保证"再怎么堆也会空，再怎么差也能打中"。

### 2. 伤害计算

```
原始伤害 = rand(攻击下限, 攻击上限)
减伤     = rand(防御下限, 防御上限)
最终伤害 = max(0, 原始伤害 - 减伤)
```

**`最终伤害 == 0` 时产生 `Blocked` 事件，日志显示"XX 抵挡了你的攻击"** —— 这是传奇最标志性的手感，必须保留。它也天然创造了"防御穿不过去就必须换装 / 升级"的卡点，正好当增量游戏的关卡门槛。

### 3. 法术伤害

同上，但用 `MC`/`SC` 对 `MAC`，且**法术不判定命中**（传奇里法术基本必中）。

### 4. 攻击节奏

```rust
// 战斗状态机
struct Combat {
    monster: MonsterInstance,
    next_player_attack_at: Tick,   // 玩家下次出手
    next_monster_attack_at: Tick,
    next_skill_ready_at: [Tick; N],// 各技能冷却
}
```

玩家攻速 1.2s = 12 tick。怪物各自有自己的攻击间隔。

### 5. 自动喝药

挂机游戏必须有自动续航，规则可配置：

```
HP < 50% 且 背包有金创药 → 喝（取能回满的最小规格，避免浪费）
MP < 30% 且 背包有魔法药 → 喝
无药可喝 且 HP < 20%     → 停止战斗，自动回城（见下）
```

> ✅ **已定（ADR-007）**：可调 + 调节精度随进度解锁。
> **实现分两步**：T4 先用 `balance.ron` 里的固定阈值跑通，T14 再做成解锁链：
> 开关 → 粗调（25%/50%/75%）→ 精调（1% 步进）→ 药水规格偏好。
> 阈值配置属于角色存档，不是全局配置。

### 6. 死亡惩罚

传奇原版死亡掉经验、有概率掉装备 —— 对挂机游戏太狠（玩家睡一觉回来可能倒退）。建议削弱：

```
死亡 → 损失当前等级经验条的 5%，不掉级，不掉装备
    → 自动传送回当前地图的"安全区"，休息 30 秒（300 tick）后继续
```

> ✅ **已定（ADR-002）**：默认不掉装备，另提供可选的**高风险模式**。
>
> | | 默认 | 高风险模式 |
> | --- | --- | --- |
> | 掉落率 | 基准 | **+50%** |
> | 死亡惩罚 | 经验条 5% | 经验条 5% + **掉一件未锁定装备** |
>
> 高风险模式在**角色创建时选择，创建后不可更改**（否则玩家会在安全区开、战斗前关）。
> 配套需求：装备的「锁定」标记 + UI 操作；角色列表里高风险角色要有显著标识。

## 挂机与自动化

### 自动战斗逻辑（玩家可配的优先级列表）

```
1. 如果 HP/MP 低于阈值 → 喝药
2. 如果 有可用的爆发技能 且 怪物 HP > X% → 放技能
3. 如果 场上有怪 → 普攻
4. 如果 场上无怪 → 等待刷怪（刷怪间隔由地图定义）
```

### 地图自动推进

```
在当前地图击杀数达标 / 等级达标 → 提示可前往下一张地图
                              → 玩家开启"自动推进"后自动切换
```

"自动推进"本身应该是一个**解锁项**（挂机游戏的经典设计：自动化能力是最好的奖励）。

### 挂机效率的成长点

这是增量游戏的真正主体，建议的投入产出项：

| 项目 | 消耗 | 收益 |
| --- | --- | --- |
| 装备强化（武器升级） | 黑铁矿 + 金币 + 首饰 | 攻击上限 +1 ~ +3 |
| 技能升级 | 技能书 + 熟练度 | 伤害 / 冷却 |
| 商店补给上限 | 金币 | 一次能带更多药（挂更久） |
| 自动化解锁 | 金币 / 成就 | 自动喝药、自动换地图、自动卖垃圾 |
| 行会 / 称号 ⚠️ | 成就 | 全局微幅加成（纯增量游戏元素，非原作） |

### 武器升级（传奇特色，必做）

传奇的"武器升级"是赌博式玩法，天然适合增量游戏：

```
投入：武器 + 黑铁矿石(纯度) + 首饰(决定加成方向) + 金币
结果：成功 → 攻击上限 / 下限 / 准确 提升
      失败 → 武器碎掉（！）
成功率随已升次数递减
```

> ✅ **已定（ADR-003）**：失败碎裂，但有**幸运符**可保护（失败时消耗幸运符，武器保住）。
> 幸运符靠挂机掉落获取 —— 于是挂机时长本身成为赌博资本，把纯 roll 点转化成资源管理。
> **UI 要求**：必须显示当前成功率 + 二次确认，绝不能手滑触发。

## 经验与等级曲线

```
Lv.N → Lv.N+1 所需经验 = round(BASE * N^2.4)
```

幂律而非纯指数，前期升级快（多巴胺），后期自然放缓。具体 `BASE` 和指数放在 `data/balance.ron` 里，便于调参而不用重编译。

地图的经验产出应该让**每张地图"够用"约 3–5 级**，之后效率明显下降，逼着玩家往下一张地图走。

## 掉落

每只怪一张掉落表：

```ron
drops: [
    (item: "gold",            chance: 1.0,     min: 80, max: 150),
    (item: "potion_hp_small", chance: 0.35,    min: 1,  max: 3),
    (item: "zuma_helmet",     chance: 0.002,   min: 1,  max: 1),
]
```

- 每项独立 roll（不是互斥权重表）—— 更接近传奇"一只怪可能同时掉好几样"的感觉
- 稀有掉落（`chance < 0.01`）单独产生高亮事件 + 可选音效（终端 bell）
- **保底机制**：建议给稀有装备加 pity 计数器（击杀 N 次必掉）。原作没有，但对挂机游戏很重要，否则玩家可能挂一整天颗粒无收。

> ✅ **已定（ADR-004）**：加保底，阈值设为**期望次数的 3 倍**。
> - 只对 `chance < 0.01` 的掉落项启用
> - 阈值由掉率自动推导（`ceil(3 / chance)`），不手工配置，避免数据表膨胀
> - `GameState` 需要 `pity: BTreeMap<(MonsterId, ItemId), u32>`，随存档序列化
> - **保底触发的掉落在日志里不要特殊标注** —— 玩家一旦知道是保底，惊喜感就没了

## 新手 15 分钟体验设计

挂机游戏的留存全在开头，照这个节奏排：

| 时间 | 事件 |
| --- | --- |
| 0:00 | 选职业，出生在比奇省，打鸡 / 鹿 |
| 0:30 | 第一次升级（Lv.2），第一本技能书掉落 |
| 2:00 | 第一件装备掉落（木剑 / 布衣），感受换装带来的数值跳变 |
| 4:00 | 解锁第二张地图，提示"你可以自动推进了" |
| 7:00 | 遇到第一个"抵挡"墙 —— 怪物防御吃光伤害，引导去商店 / 强化 |
| 10:00 | 解锁自动喝药 |
| 15:00 | 第一个精英怪 / 小 BOSS，第一件绿色品质装备 |

## 平衡调参

所有系数集中在 `data/balance.ron`，不散落在代码里：

```ron
(
    exp_curve: (base: 100, exponent: 2.4),
    hit_chance: (base: 0.75, per_point: 0.05, min: 0.15, max: 0.98),
    death_penalty_exp_pct: 0.05,
    death_rest_ticks: 300,
    offline_cap_hours: 12,
    upgrade_success_rates: [0.95, 0.85, 0.70, 0.50, 0.30],
)
```

配合 `insta` 快照测试：固定种子跑 N 个 tick，把"Lv.X 时的属性 / 累计金币 / 击杀数"存成快照。改公式时 diff 会直接告诉你平衡偏移了多少。这是整个项目里**性价比最高的一项测试投入**。
